## Reproducibility details and corrections
RF-DETR source distribution 1.4.3 SHA256: `7595655930576cb3c2bccd5fa9fa7b3a3b3526f09e42450af143debaaa15ab53`; BoxMOT16.0.10 source distribution SHA256: `50626aae3e599aa75003b71855e1b0fdfbbf2c36378350297412251afc75ed93`. These hash **source archives**, not model weights or installed environments. [RF PyPI](https://pypi.org/project/rfdetr/1.4.3/) and [BoxMOT PyPI](https://pypi.org/project/boxmot/16.0.10/) supply versioned metadata. BoxMOT distribution16.0.10 contains a stale internal `__version__` string16.0.9; record `importlib.metadata.version('boxmot')`, not that string.

The inspected [GSR PRT config](https://github.com/SoccerNet/sn-gamestate/blob/1c958345067218297d221e45e1a6405f975f83e0/sn_gamestate/configs/modules/reid/prtreid.yaml) selects **`test_embeddings: ["globl"]`**. Its adapter supports parts, but its default is not evidence of a full part-aware run. This refines any broader wording in the prior audit. Global/parts must be evaluated separately using the same exact crops/checkpoint and fully specified head/distance normalization.

### Controlled upstream extraction specification (BLOCKED until implemented/validated)
1. Create an isolated upstream-compatible Python environment; pin its original repo, model config and checkpoint+HRNet hashes. Do not train. GSR's README advice to enable PRT training is not needed/authorized for inference.
2. Build the exact upstream config matching the checkpoint; disable automatic pretrained downloads and point to reviewed local assets. Do not guess `num_classes` or silently accept a partial weight-load warning. Archive loaded/missing/unexpected keys and fail unreviewed architecture mismatches.
3. Use upstream `FeatureExtractor(cfg, model_path=..., image_size=(256,128), device='cuda', verbose=False)` with a **list of RGB image paths**. Single-string/array branches have different mask assumptions in inspected source. Preserve that upstream preprocessing rather than duplicating it here.
4. Use upstream `extract_test_embeddings`. PRT model output has eight tuple fields and returns five extracted outputs; BPB output has six fields and extractor utility returns four. Do not assume they are interchangeable. Export original head keys, `[N,P,D]` features and visibility/masks in canonical crop order.
5. Global condition selects `globl`; full-part condition selects a recorded part head (e.g. `parts`) plus any explicitly chosen global/foreground head. `bn_*` heads are separate conditions. Call the upstream visibility-aware distance routine with its exact mean/max/metric options; preserve no-common-visible-part sentinels as **unmatchable**. Score on the same query/gallery lists.
6. Export environment/config/runtime/asset provenance and `export.json` file hashes. Validate dimensions, head keys, crop order, finite norms and output contract on a tiny fixture before enabling the full benchmark. This lab supplies a bridge validator and specification, **not a proven executable PRT/BPB integration**.
