# Experiment plan and preregistration

All criteria below are **proposed decision thresholds**, not measured results, model guarantees or final Scoutra product requirements. Freeze them on development data before opening independent test matches. Small datasets may support no statistically credible winner.

## Shared controls
Use exact input frame/crop/decode hashes, match-disjoint groups, reviewed annotations and scene boundaries. Set seed1729 for applicable stochastic routines, log deterministic warnings, source pins, checkpoint/directory hashes, class maps, method defaults, resolution, batch/dtype and device. No tuning on test. Per-method resolution may be native first, but label compute-unmatched comparison; add matched resolution/budget only when technically valid. An existing Scoutra baseline stays N/A until its real checkpoint/config/results are available.

Run one model on one GPU for isolated timing. Repeat at least three independent runs with identical settings for median/range; CUDA synchronize before/after. Record model load separately and full inference/preprocessing/I/O scope. Current tracking scope includes tracker construction/reset and associated Re-ID loading per scene; detector/OSNet extraction loading is outside their measured scope. These timings must be labeled accordingly. Add CPU RSS and device-wide NVML sampling in a later validated measurement harness if required; current allocated/reserved PyTorch peaks do not equal all-process VRAM. Do not compare advertised TensorRT A100 numbers with this PyTorch T4 experiment.

Bootstrap paired **per-match** deltas; report match/clip/player/episode counts and95%intervals. `paired_match_bootstrap` refuses inferential intervals for fewer than five independent matches. Five is not a power calculation. Report effect sizes and practical margins; wide uncertainty means inconclusive. Do not treat thousands of correlated frames from one clip as independent samples. Test easy/hard, size, camera and visibility bins separately; do not conceal regressions in a mean score.

## A — Detection
Hypothesis: the best football detector depends on small-player/ball visibility and resolution more than generic COCO ranking. Dataset: identical reviewed exhaustive frames, actual source-match split, role labels for player/goalkeeper/referee. Methods: true Scoutra RF-DETR if supplied; generic RF-DETR Small/Medium; official D-FINE S (N separate optional budget condition); HF RT-DETR R50-vd. No training.

Outputs: canonical saved detections at0.05 score floor, explicit raw class map, run metadata. Metrics: COCO AP50–95/AP50, class-specific AP using official evaluator if required, player/keeper role recall, ball recall, FP/frame at matched validation-selected operating points, height/area bins and camera scenarios. Current code automates aggregate COCO AP and class/size/camera recall/FP; perclass AP and matched-FP sweep need an additional recorded evaluation pass, not an invented metric. Save exact cutoff and score-floor effect.

Hardware: one T4, batch1 starting point, native frame cache. Success proposal: >=5percentage-point tiny-ball recall improvement at matched FP/frame, with <=2point player-recall loss; 95%paired interval and practical significance considered together. Failure: uncertainty/regressions, unreviewed class mapping, or memory failure. Save predictions to freeze shared detections for B; selecting the detector is based on development matches only.

## B — Local tracking
Hypothesis: camera-motion compensation and appearance help on pan/occlusion, but can amplify same-kit false associations. Methods: supervision ByteTrack, BoxMOT BoT-SORT/StrongSORT ports, exact McByte++ via validated bridge. Feed the same low-threshold detections and all consecutive frames/empty detections. Do not rerun a hidden detector. Separate BoT-SORT appearance on/off and CMC variants as named ablations. McByte mask extraction is counted; if its interface cannot consume the same detections, declare a different detector condition and do not attribute gain solely to tracker.

GT: dense physical-ID boxes, selected anchor, reviewed occlusion intervals. Metrics: official TrackEval HOTA/DetA/AssA/IDF1/IDSW/Frag; supplemental matched tracklet purity, unmatched predictions, anchor identity precision/coverage. Report switched identity error timelines. Current supplemental switch/fragment counts on reviewed frames are not official CLEAR counts. Visualize using the exact frame cache and white GT overlays. Hardware: T4 feature extraction/CPU association, independent timing. Success proposal: >=20%relative ID-switch reduction on hard scenes without >0.5point selected-player precision loss; no new clearly harmful false merge class. If too few errors/matches for a reliable delta, conclude inconclusive.

## C — Re-identification
Hypothesis: football-trained PRT features, especially visibility-aware parts, improve same-team recovery beyond OSNet; tiny/occluded crops may invalidate that hypothesis. Methods: OSNet x0.25 MSMT17; PRTReID `globl`; PRT full parts+visibility; BPB full parts+visibility. Same labeled pixels/query/gallery/tracklets; preserve upstream method preprocessing. Separate global/parts from generic replacement embeddings. Run no fine-tuning.

Dataset: same-team hard negatives and true cross-tracklet positives, viewpoint/visibility/pixel-height/time-gap metadata. Exclude same-crop/track leakage and adjacent near-duplicates. GT-crop and predicted-track-crop conditions are separate. Metrics: Rank1/mAP, false-match rate at locked validation threshold, TPR/recovery at fixed FMR, no-visible-parts abstention and calibration. Current generic scorer supplies Rank1/mAP and TPR/FMR at an explicit validation-chosen threshold; fullpart upstream distances and stratified evaluation must be validated before quantitative comparison. Hardware: single T4, small batches; legacy methods separate compatible environment. Success proposal: >=10point recovery gain at <=0.5%false-match rate, and no material same-team regression; require enough negative pairs and independent matches to bound that rate. Zero errors in a tiny sample does not establish0.5%risk.

## D — Global identity recovery
Hypothesis: splitting contaminated tracklets before linking reduces false merges; aggressive merge-only linking may improve coverage while hurting identity precision. Methods: no-link baseline; pinned AgentCoach ReID-only (and later predicted-team/OCR variants); upstream GTA split+link; McByte++ bank on/off; combinations only after feature/score/temporal compatibility is confirmed. No GT teams/numbers or GT-driven split decisions as deployment input. Tune thresholds on validation, lock before test.

Dataset: reviewed cross-gap episodes, known physical IDs, ID-contaminated local tracks and clean controls. Metrics: anchor-selected precision/coverage, correct recovery after return and delay, false merges per100eligible links, contaminated-track detection precision/recall, wrong splits, false-confident assignments, unknown fraction. Include separate assignment-risk/coverage curves. Current scorer supplies anchor precision/coverage, contaminated predicted-ID counts and pair counts; episode/split/confidence curves require reviewed episode annotations and a validated extension. Threshold/cosine scores are not calibrated confidence. McByte online bank and offline global linker are different timing/information regimes; report latency/lookahead, not one unlabeled leaderboard.

Hardware: CPU offline features/distances with bounded batches; T4 only if upstream representation/masks require it. Success proposal: >=10point recovery-coverage gain with no >0.5point precision loss and no increase in false merges; require upper error bounds compatible with selected-player use, otherwise prefer unknown. Any incorrect confident target attribution is a separately reviewed severe failure.

## Progression gates (manual, never automatic)
| Stage | Data | Required evidence to proceed |
|---|---|---|
|1:20–60s | multiple short continuous easy/hard shots; independent match holdout where possible | assets/install/output-contract pass; complete review labels for quantitative claims; all methods use same caches; no unresolved severe selected-ID attribution; report uncertainty. Provisional selected precision>=99%, visible coverage>=70%, plus sufficient independent sample size to assess these figures |
|2:2–3min | unseen continuous clips, true re-entries and camera motion | retain Stage1 precision floor and <=2point degradation; episode false merges below preregistered risk bound; document unassigned coverage and error accumulation |
|3:5–10min | untouched continuous clips, imposed chunk boundaries and interruption | deterministic immutable-stage replay; no duplicate/gap frames; correct stage resume/reprocess; bounded RAM/VRAM; no>2point precision loss versus unchunked reference; identity bank serialization verified. Current Stage1 code does not implement these features |
|4:45–90min | actual full matches incl halftime/substitutions | Stage3fault tests pass; match-disjoint full-match GT subset; period/roster/cut policy and unknown handling; all identity/calibration/event claims auditable; measured throughput and storage within a declared operational budget |

The99%/70%and regression margins are starting proposals, not evidence that this sample can certify them. If highlights cannot supply longer uninterrupted recordings or independent matches, progression stops for data reasons. A visually good demo does not waive the gates.
