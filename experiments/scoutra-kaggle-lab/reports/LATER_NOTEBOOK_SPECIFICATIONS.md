# Later experimental families — specifications only, no model execution

## 06 — Jersey OCR
Hypothesis: multi-view, quality-gated temporal number aggregation is safer than one-frame OCR. Compare pinned upstream PARSeq and EasyOCR pipelines on the **same manually labeled native jersey crops** with unreadable/partial/no-number labels. Use [jersey-tracker source](https://github.com/spindle79/jersey-tracker/tree/e8021b51a1e021da058f4acd17e39f3d4ecb5051) as a reference, retaining model/dependency grants. Record number confusion, exact digit accuracy, readable coverage, abstention, per-track number purity and false identity merges when OCR becomes a constraint. Aggregate only clean tracklet evidence; do not allow an OCR misread to relabel a player confidently. Single T4 candidate, exact weights/hash/stack still to select. Success: lower track-level false-number assignments at matched coverage on held-out matches; failure: unreadable guesses or unstable numbers silently used as hard constraints.

## 07 — Camera calibration
Compare manually specified OpenCV homography with TVCalib on identical frames/landmark labels. Fixed camera: one stable model plus drift checks. Pan/zoom: time-varying calibration; reset at cuts. Survey actual youth pitch dimensions, do not assume105×68m. Evaluate held-out reprojection error in pixels/metres, footpoint/world error, temporal jitter and speed/distance sensitivity. Use RANSAC/outlier rejection policies fixed before test. CPU homography first; TVCalib own GPU environment/checkpoints as specified in the prior audit. Success: independent landmark/coordinate error acceptable for a declared analytics tolerance; failure: pretty minimap with unquantified geometry or non-ground-plane feet. No speed/distance product metrics before coordinate validation.

## 08 — Ball tracking
Use frozen detector results, dense reviewed ball visibility/occlusion labels and exact scene boundaries. Compare motion-only trajectory filtering against a documented ball-specific model/temporal approach only after assets are verified. Evaluate visible-ball recall, center error vs diameter, false trajectories, recovered gap length and possession sensitivity; mark invisible ball unknown. Ball is not a person-ReID class. T4 candidate; high-resolution crops/slicing cost and timing counted. No inferred possession ground truth from the same tracker being evaluated.

## 09 — Event spotting and actor attribution
Compare [OpenSportsLib](https://github.com/OpenSportsLab/opensportslib) spotting baselines and [FOOTPASS actor-centric source](https://github.com/JeremieOchin/FOOTPASS/tree/f63f37c1a0c6bcebf568a8ce716495a459376af5) only after exact repository/model/data grants, tracks/roles/features and environment are available. FOOTPASS source-license conflict and gated data remain blockers. Use common event definitions, scored negative windows, independent physical actor IDs and timing. Metrics: perclass precision/recall/AP across declared temporal tolerances, actor accuracy conditional on correct event, joint actor+time correctness, unknown actor coverage and class imbalance. Keep GT-track oracle separate from predicted-track deployment. Test rare events and unseen venues. Success: gains persist in joint actor+time metric at matched false positives; failure: generic event success with wrong player credit. No immediate all-model run.

## 10 — Video-VLM clip understanding
Hypothesis: a small football-adapted VLM improves clip event reasoning but does not replace fine-grained coordinates or persistent identity. Compare one general Qwen3-VL8B baseline with a compatible football specialist (SoccerChat/OSL-XFoul), and newer Qwen3.5small only in its supported independent environment. Audit exact base/adapter revisions and labels. acato's32B soccer v11 is a later larger-memory reproduction target; its amateur/youth focus is relevant, but private training provenance and license mismatch remain limitations. See `previous-audit/VLM_RESEARCH.md` and MODEL_INVENTORY for direct pinned cards.

Pair each football adapter with its exact unadapted base (e.g. SoccerChat with Qwen2-VL7B, OSL-XFoul with its specified Qwen3-VL8B base); comparisons to newer general architectures are a separate benchmark and cannot isolate the effect of fine-tuning. Same short clip windows and questions for all methods; fixed seed, max output tokens, decoding settings and abstention schema. Record true FPS/PTS, sampled frame indices/timestamps, max pixels, total visual tokens, context length, quantizer (e.g.NF4/double-quant/compute dtype), bitsandbytes/Transformers/PEFT/backend versions, adapter merge status, GPU placement/max_memory/CPU offload and actual peak. Start with a small **explicit** frame/pixel budget such as8–16frames; this is a test configuration proposal, not a confirmed fit. Inspect whether the event is even visible in sampled frames. Include counterfactual/no-event windows, same-kit actors, hidden ball and cropped goals. Record hallucinated events, invented actors/numbers, invalid JSON, unsupported certainty, timing error and joint actor+event correctness. Name descriptions are not verified physical identities.

Quantized multi-GPU inference is allowed only if the chosen model/backend implements it and a small load/memory test confirms fit. Two T4s are not pooled32GB;4-bit weights still need quantization metadata, vision encoder, activations and KV cache. T4 cannot execute every BF16/FP8 recipe. **Do not attempt32B/35B** without a documented supported full configuration and measured load headroom. H100 later is also conditional on exact variant/VRAM and backend support. No VLM inference code or model download is enabled now.

## 11 — Long-video and fault recovery
Requires real2–3min,5–10min and45–90min **continuous** recordings, not stitched highlights. Test staged decode→detections→features→local tracks→offline association→events. Cache detector/features once; heavier ReID/OCR/VLM runs only on selected uncertain/quality windows. Run low-cost local methods continuously; selected event proposals invoke VLM. Record detector proposal miss rate so selective VLM scheduling does not hide missed events.

Compare unchunked reference with chunk durations/overlap chosen on development data, owning each frame exactly once and de-duplicating overlap by source frame/detection IDs. Carry or explicitly restart local motion state; preserve global bank/prototype/version with provenance. Halftime and substitutions need period/roster logic and unknown identity, not automatic number equivalence. Inject interruption between and within stages; resume only from integrity-checked completed artifacts, recompute failed segments, avoid duplicate committed outputs. Do not claim the current Stage1 atomic writes provide bank-resumable processing. Test bounded queues/stream decode, pairwise-candidate memory limits, retained part features, CPU↔GPU transfer cost and stage parallel contention. T4s initially run independent isolated stages/jobs; H100 later tests batching/scheduling with exact measured settings.

Success: identical committed source-frame coverage and consistent identities after restart, no silent result holes/false merges, bounded measured memory, measured throughput with scope. Failure: local ID resets treated as physical substitutions, stale/broken caches, overlap double counting or unknown videos collapsed into one match.
